# Pantau Bergizi Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fresh Next.js 16 repo with Postgres schema, seed data, signed-cookie staff login, route stubs, a daily simulated-data top-up, and a live Vercel deploy.

**Architecture:** One Next.js App Router app at the repo root. Drizzle over postgres.js talks to Neon in prod and a local Postgres (Postgres.app 18) in dev, tests and offline demo. Auth is hand-rolled: scrypt password hashes plus an HMAC-signed cookie, checked next to data access through `requireRole()`.

**Tech Stack:** Bun 1.4, Next.js 16, React 19, TypeScript strict, Tailwind 4, shadcn/ui (`iconLibrary: "phosphor"`), `@phosphor-icons/react`, Drizzle ORM + drizzle-kit, `postgres`, Zod, `bun test`, Vercel Hobby, Neon free.

**Spec:** `docs/superpowers/specs/2026-10-29-scaffold-design.md`. Product context: `PRD_Pantau_Bergizi_V2_1.md`.

## Global Constraints

- Use Bun for everything: `bun add`, `bun run`, `bunx`. No npm/pnpm lockfiles.
- Code, tables, columns and enum keys are English. Routes and all UI copy are Indonesian.
- Status keys are `priority | attention | no_signal | no_data`. Labels are "Prioritas", "Perlu perhatian", "Tidak ada sinyal" and "Belum ada data".
- No `any`. Infer types from the Drizzle schema (`typeof table.$inferSelect` / `$inferInsert`) and Zod (`z.infer`).
- Never commit secrets. Commit `.env.example` and `.env.test` (dummy values only); gitignore every other `.env*`.
- Never commit `PPT Technical Meeting MIA 2026.pdf`.
- Thresholds are only read from `src/lib/thresholds.ts`.
- Next.js 16 has breaking changes. Read `node_modules/next/dist/docs/` for any API you're unsure of (`cookies()` is async; server actions use `"use server"`).
- Conventional commit messages, each ending with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Dev DB: `postgres://localhost:5432/pantau_bergizi`. Test DB: `postgres://localhost:5432/pantau_bergizi_test` (Postgres.app, current user, no password).

## Review Focus

1. **Cron runs at 22:00 UTC, which is already tomorrow in WIB.** Top-up must date reports by the WIB calendar day, not UTC. Pinned in Task 6 (`todayWIB` test).
2. **Neon's pooled URL with postgres.js.** Prepared statements break behind PgBouncer transaction mode, so the client must set `prepare: false`. Pinned in Task 3 (client option) and verified live in Task 9.
3. **Demo users who log in with `Moderator@...` or trailing spaces** expect to get in. Pinned in Task 4 (`authenticate` normalizes email).
4. **Sessions issued before a manual reset must still point at the same demo users.** Reset uses `TRUNCATE … RESTART IDENTITY CASCADE` and seed order is fixed. Pinned in Task 5 (ids stable across two resets).
5. **Top-up must never insert reports with `received_at` in the future.** A 05:00 WIB run must not create "lunch" reports at 12:00. Pinned in Task 6.

### Task 4: Auth core (passwords, signed session, authenticate)

**Files:**
- Create: `src/lib/auth.ts`, `src/lib/auth.test.ts`

**Interfaces:**
- Consumes: `Db`, `user` from Task 3.
- Produces:
  - `type Role = "moderator" | "sppg_manager"`
  - `type Session = { uid: number; role: Role; sppgId: number | null; exp: number }` (`exp` is a unix-seconds expiry time)
  - `SESSION_TTL_SECONDS = 8 * 60 * 60`
  - `hashPassword(plain: string): Promise<string>` returns `"<saltHex>:<hashHex>"` (scrypt, 16-byte salt, 64-byte key)

  - `authenticate(db: Db, email: string, password: string): Promise<Omit<Session, "exp"> | null>` trims and lowercases the email; returns null for an unknown email or a wrong password.
